# Post-update geographic migration

This process is run by `yllir:process-runner` after framework alignment when the independent geographic migration marker is pending. It is separate from the Statistics and item-description migrations. It never speaks to the master directly and never applies moves outside `yllir:write-sequence`.

Use the campaign language from `campaign.yaml`. Keep unresolved facts and contradictions pending. Never infer a scene appearance from `characters`, `items`, names, links, or mentions. The only appearance metadata is `appearances: [{subject: ID, location: [PLACE_IDS]}]`, supported by the explicit scene text.

## Steps

1. Read `campaign.yaml`, the campaign language, the active topic handoff, and the complete plot events and relevant place and subject sheets. Keep the original event paths. Do not move or rename events.
2. Run `node "${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/skills/core/write-sequence/scripts/geographic-layout.mjs" . plan --out .campaign/state/write/geography-scan.json`. In Codex without either plugin-root variable, use the absolute installed plugin path. Read its JSON result. If it is blocked or has errors, return FAILED with no campaign writes. If `migrationRequired` is false, run `node "${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/skills/core/update/scripts/update-campaign.mjs" . --complete-geography` and finish DONE only when it reports completion.
3. For each legacy event whose text clearly establishes who is physically present and where, prepare a draft adding the matching explicit `appearances` metadata. Preserve every existing field and all document text. Do not add or infer a current `location` for the subject from a past scene. If a name or place is ambiguous, a claim conflicts with another source, or presence is not explicit, leave it out and record the event and reason as pending. Ask one question when the migration cannot safely continue without the master's decision.
4. Apply the layout through `yllir:write-sequence`. The write sequence builds the geographic plan from the drafts, reviews it together with them, applies it, then links and checks the canonical paths. Do not run the plan separately before it.
   - If there is at least one event draft: write each draft with the Write tool to `.campaign/state/write/draft/<same path>`, where `<same path>` is the original campaign-relative event path. Then invoke `yllir:write-sequence` with `DOCUMENTS` set to the event paths, `INTENT` set to "Record only text-supported scene appearances for the geographic layout; no other text changes.", `NEW_SUBJECTS` empty, the relevant places and subjects as `CONTEXT_FILES`, `ROUND=1`, `CONTINUE_WITH="post-geography step 5: read the write report and act on its status"`, and the version message "Recorded explicit scene appearances for the geographic layout." translated into the campaign language. Event source files remain in their session folders; geographic views are symlinks.
   - If there are zero event drafts (the migration is required, but no event needs new `appearances`): write no draft. Invoke `yllir:write-sequence` with `DOCUMENTS: none` (layout only), `INTENT: "Arrange existing sheets by place from their explicit location data; no text changes."`, `NEW_SUBJECTS` empty, `CONTEXT_FILES` empty, `ROUND=1`, `CONTINUE_WITH="post-geography step 5: read the write report and act on its status"`, and the version message "Arranged the sheets by place." translated into the campaign language.
   - If write-sequence returns FIX_NEEDED because of plan errors, report the first plan error as FAILED, or ask one question if the master's decision is needed.
5. Read `.campaign/state/write/report.txt` with the Read tool and act on its `status:` line:
   - `DONE`: rerun the plan without overlays: `node "${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/skills/core/write-sequence/scripts/geographic-layout.mjs" . plan --out .campaign/state/write/geography-scan.json`. If it reports `migrationRequired: true` only because there are still pending events, preserve the marker and return QUESTION or FAILED as appropriate. If the plan has no errors and migration is complete, run `node "${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/skills/core/update/scripts/update-campaign.mjs" . --complete-geography` and finish DONE only when it confirms completion. A changed source, failed plan, failed application or failed verification leaves the marker pending. Never claim completion based on an empty-looking folder or an inferred appearance.
   - `FIX_NEEDED`: read the problems listed under `details` in the report. If there are event drafts, fix only those problems in the drafts in `.campaign/state/write/draft/`, never adding an appearance that the scene text does not support, and invoke `yllir:write-sequence` again with the same other inputs and `ROUND` plus one. Use at most three rounds: after a FIX_NEEDED at ROUND 3, finish FAILED and keep the marker pending. In layout-only mode there are no drafts to fix: finish FAILED with the first error.
   - `ASK`: finish QUESTION with the question from the report, in plain words. The marker stays pending.
   - `VERIFY_FAILED` or `FAILED`: finish FAILED. The marker stays pending.
   - Any other status: finish FAILED. The marker stays pending.
6. On resume, read the topic handoff and the master's answer. Preserve all accepted drafts and prior completed work. Re-read any changed event and recompute the full plan before continuing.

## Result

Write `.campaign/state/runner/result.txt` in the exact format from `yllir/agents/process-runner.md`. For DONE, say that the geographic arrangement is ready. For QUESTION, ask one clear question about the first unresolved fact. For FAILED, say that the arrangement could not be completed. List only canonical paths where needed in the internal `files written` field; never expose private-note text.
