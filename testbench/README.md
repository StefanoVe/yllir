# Testbench

The testbench holds synthetic campaigns, each with an answer key, and the runners that run the framework's Claude Code agent on them and grade what it does.

- `fixtures/morvalle/campaign/`: a synthetic campaign in the current format (after the world-graph migration). It is the only part an agent under test works on.
- `fixtures/morvalle/key.yaml`: the answer key for the mention scanner and the continuity audit: what must be found and what must not.
- `fixtures/morvalle-seeded/campaign/`: the same campaign with three constraints seeded in the world seed (a faction, a family naming rule and something to avoid). Only the `world/region` case uses it. Its answer key is `cases/world/region/key.yaml`.
- `fixtures/continuity/campaign/`: a small synthetic campaign for the library skill `continuity-keeper` (rename with a homonym, delete with a dependent document, merge with a conflicting fact, retcon of a played chronicle). Its traps are listed in `fixtures/continuity/README.md`. Each answer key is `cases/continuity/<name>/key.yaml`.
- `fixtures/atlas-morvalle/campaign/`: the Morvalle campaign plus a second region (Valdaspra), two wells with the same title, a hidden refuge and no stated direction for one well. Only the atlas cases use it. Its traps are listed in `fixtures/atlas-morvalle/README.md`; each answer key is `cases/atlas/<name>/key.yaml`.
- `fixtures/atlas-ostrava-town/campaign/`: a synthetic walled river town (Bornago) with two districts and a homonym. Only the atlas city case uses it; its traps are listed in `fixtures/atlas-ostrava-town/README.md`.
- `fixtures/fabula-ultima/`: an English campaign with the fabula-ultima adapter. Its traps are in its README; its answer key is `fixtures/fabula-ultima/key.yaml`, checked offline by `runners/fabula-fixture.test.mjs`. Only the system cases use it.
- `fixtures/plot-missions/` and `fixtures/plot-seasons/`: two plot structures, one with missions and one with seasons and chapters. Their traps and Findings are in their READMEs; their keys are `key.yaml`, checked offline by `runners/plot-structures.test.mjs`. Only the plot cases use them.
- `fixtures/import-interrupted-input/`: the input of the import case (`import/interrupted`). The runner makes a truncated PDF from it in the copy; the traps are in `fixtures/import-interrupted-README.md`.
- `fixtures/morvalle-legacy/campaign/`: a frozen copy of the same campaign before the world-graph migration (no `kind`, `provenance` or relations, and no seed). Only the update cases use it, because they need the old format.
- `cases/<kind>/<name>/case.yaml`: one case: the master's message, the expected behaviour and its limits.
- `runners/`: the scripts that run a case or grade a component against its key.
- `results/<case>.jsonl`: one JSON line per run, appended by the runners.

Rule: an agent under test receives only a COPY of a campaign. It never sees `key.yaml`, because an agent that can read the key measures copying, not finding. Runners read the keys from the repository.

## Agent and model

Only Claude is tested. The case runners call `claude -p` with the plugin in `yllir/`.

- Default model: `sonnet`. The author is the main agent and must be a strong model. `--model <name>` overrides it (for example `--model haiku` to measure an executor). Each record stores the model it ran with.
- Permissions are strict, as in a real master's campaign: `claude -p` gets `--permission-mode manual --permission-prompts none` (anything that would prompt is refused, nothing is asked) and `--settings runners/lib/strict-settings.json`, which holds the project permissions generated by the framework from the `allowed-tools` of every skill (`Skill(yllir:*)`, `Edit(.campaign/state/**)`, `Edit(.campaign/drafts/**)` and one `Bash(node "*/<script>" *)` rule per plugin script). Nothing else is granted. The file is kept equal to the generated text by `node testbench/runners/lib/sync-strict-settings.mjs --write`. Each record stores `permission_mode: "strict"`.

## Limits

A case may declare a `limits` mapping in `case.yaml`:

```yaml
limits:
  max_minutes: 3
  max_tool_calls: 126
```

Both keys are optional; a key that is given must be a positive number. The shared functions in `runners/lib/case-common.mjs` do the work for every runner:

- `parseLimits(data)` reads the mapping (or returns `null` when the case has none).
- `applyLimits(graded, limits, run)` turns the run result (`duration_ms` and `tool_calls` of `runClaude`) into the checks `L-time` and `L-calls`, adds their reasons to `failures` and requires them for `pass`. A value that was not measured fails its check. Each runner stores `limits` in its record.

A run that exceeds a limit fails. The current values:

| Case | max_minutes | max_tool_calls | Basis |
|---|---|---|---|
| `new-campaign/*` | 4 | 60 | target: new campaign |
| `entry/prepare-proceed`, `entry/prepare-two-turns` | 3 | 126, 146 | target: prepare session; calls about 1.5x the median (84, 97) |
| `entry/after-proceed` | 3 | 77 | target: after session; calls about 1.5x the median (51) |
| `entry/after-too-thin` | 3 | 60 | target: after session |
| `entry/go-back`, `entry/where-and-question`, `entry/not-available`, `entry/question-hypothesis` | 2 | 60 | target: entry questions |
| `update/*` | 5 | 60 | target: update (no recorded runs yet, so the call limit is the default) |
| `audit/full` | 10 | 140 | target: audit; calls about 1.5x the median (93) |
| `world/region` | 10 | 200 | target: a region of about 30 subjects in 5 to 10 minutes (section 11, «Misura», of `docs/Riprogettazione.md`) |
| `world/creature` | 3 | 60 | target: one enemy sheet, the same budget as the entry cases |
| `atlas/create-asks` | 6 | 120 | target: the atlas question on a campaign with no atlas |
| `atlas/update-keeps-land` | 8 | 160 | target: an added place on a locked land (agent update) |
| `atlas/players-no-secrets` | 4 | 60 | target: the players' version of the atlas |
| `atlas/city-from-picture` | 6 | 120 | target: a city atlas from a picture in the sources |
| `import/interrupted` | 8 | 100 | target: an import cut off halfway, with its sources kept |
| `plot/*` | 6 | 140 | target: one new plot activity on an existing plot structure |
| `system/fu-*` | 3 | 60 | target: one system-rule question or fight state, the same budget as the entry cases |

The minute targets come from the redesign document («Tempi misurati»). Note that the medians recorded there for prepare-session (6.5 min) and after-session (3.4 min) are above the 3-minute targets, so those cases will fail on time until the framework is faster. The tool-call limits come from `results/*.jsonl` (haiku runs).

Every case also has `L-time` and `L-calls` when it declares limits.

Entry cases (what the checks now read):

- The work note `.campaign/state/work-note.md` is written at every commit. A case that saves (prepare, after-session) checks that it exists (P8). A case that stops before a commit (the two-turn first message, the too-thin evening, the conflict question) checks that it does not exist (Q2, C3, T3) and that the message asks exactly one question (Q2, T2).
- The saved version count grows by exactly one and the newest version is a framework version (P9). The engine deletes its review file after the commit, so the version is the evidence.
- The session main file is derived by the engine and must say `generated: true` (P1).

Run one case (costs money, takes minutes per run):

```sh
node testbench/runners/run-new-campaign-case.mjs testbench/cases/new-campaign/all-answers [--runs N] [--model sonnet] [--keep]
node testbench/runners/run-new-campaign-case.mjs testbench/cases/new-campaign/all-answers --grade-only <dir>
node testbench/runners/run-entry-case.mjs testbench/cases/entry/go-back [--runs N] [--model sonnet] [--keep]
node testbench/runners/run-entry-case.mjs testbench/cases/entry/go-back --setup-only
node testbench/runners/run-entry-case.mjs testbench/cases/entry/go-back --grade-only <dir> --run-json <dir>.run.json
node testbench/runners/run-update-case.mjs testbench/cases/update/legacy-sessions [--runs N] [--model sonnet] [--keep]
node testbench/runners/run-audit-case.mjs testbench/cases/audit/full [--runs N] [--model sonnet] [--keep]
node testbench/runners/run-audit-case.mjs testbench/cases/audit/full --grade-only <copyPath>
node testbench/runners/run-world-case.mjs testbench/cases/world/region --setup-only
node testbench/runners/run-world-case.mjs testbench/cases/world/region [--runs N] [--model sonnet] [--keep] [--judge]
node testbench/runners/run-world-case.mjs testbench/cases/world/creature --delegation always --keep
node testbench/runners/run-world-case.mjs testbench/cases/world/region --grade-only <dir> --run-json <dir>.run.json [--judge]
node testbench/runners/run-atlas-case.mjs testbench/cases/atlas/update-keeps-land [--runs N] [--model sonnet] [--keep]
node testbench/runners/run-atlas-case.mjs testbench/cases/atlas/update-keeps-land --setup-only
node testbench/runners/run-atlas-case.mjs testbench/cases/atlas/update-keeps-land --grade-only <dir> --run-json <dir>.run.json
```

With `--keep` the folder is kept and the agent's final message, cost, duration and tool calls are saved beside it as `<dir>.run.json`, so `--grade-only` reproduces the record. A `--grade-only` record of the audit does not grade the limits, because the run was not kept.

## Atlas cases

The atlas cases do not run by default, in quick mode or in release mode: the suite runs them only with `--with-atlas`. Each run is a paid agent run that builds its setup through the atlas CLI first, so run them when the atlas path changes (`atlas` skill, its scripts, the entry or update process that calls it).

Setups: `none` (the fixture only), `init` (the atlas with the procedural picture as base), `land` (init, then the land locked, one placed village, one master-only place, the master site rendered and a version saved; the baseline holds the land hash, the lock, the version count and the master site hash). The picture is `morvalle` (400 by 300, a green island with a lake and a second small island) or `town` (360 by 300, one island), chosen by the case's `picture`; `source_picture` copies it into the campaign before the baseline. The fake provider answers every job with that picture, so a provider call costs nothing and never leaves the machine.

The atlas tests run offline: `node --test runners/run-atlas-case.test.mjs runners/lib/make-atlas-picture.test.mjs`.

## World cases

A world case asks the agent for part of a world and grades the resulting world graph, not the text. The grading reads `buildWorldIndex` of the copy after the run, so no model takes part in it. The agent never sees the key: `cases/world/<name>/key.yaml` sits beside `case.yaml`, outside the fixture the runner copies. Each `key.yaml` comments its thresholds and the exact definition of every check (for example the family-name rule W7).

- `world/region`: the request is «Crea i villaggi intorno al Lago Grigio, con i loro capi e una fazione di pescatori.» on `fixtures/morvalle-seeded`. The seed holds the constraints: the family names of the lake end in -ane (graded on the graph) and no new character is a noble (not checkable on the graph, so not graded).
- `world/creature`: the request is «Mi serve un capo bandito tosto per un gruppo di terzo livello, al Borgo Cenere.» on `fixtures/morvalle` with `system.adapter: dnd-2024`. The sheet is checked with the adapter's own `validateSheet`, the function the engine uses.

Delegation (decision 16). `--delegation auto` (default) runs the plugin as it is. `always` and `never` run a temporary copy of `yllir/` in which the thresholds of `skills/core/yllir/authoring.md` and `skills/core/build-world/SKILL.md` are 0 and 999: every document is then delegated, or none is. The mode is stored in each record as `delegation`, so `duration_ms` and `cost_usd` can be compared between modes.

Quality (`--judge`). After the checks, a model distinct from the model under test (`opus` by default; `--judge-model` changes it, and an equal model is refused) reads the new documents and the seed, master-only block included, and scores specific, playable and coherent from 1 to 5. The judge gets the texts inline and no tools, because the strict permissions grant it none. `Q-grid` passes when the mean reaches `quality_min` (default 3.5). Without `--judge` there is no `Q-grid` check.

The world cases do not run by default, in quick mode or in release mode: the suite runs them only with `--with-world`. Run them only when an implementation changes the world-generation path (`build-world`, `write-document`, `sheet-expander`, `batch-reviewer`, `authoring.md`, the engine context and commit, the adapter checks). They cost money like every agent case. The suite never passes `--judge`.

## Mention scanner

```sh
node testbench/runners/check-scan.mjs [fixtureDir] [--json <file>]
```

The scanner is graded against `fixtures/morvalle/key.yaml`. A mention may set `occurrence: N` to pick the N-th scanner occurrence on its line. The scanner itself skips files whose frontmatter says `generated: true` (session main files, rebuilt by the engine), so the grader does not see them. The campaign is scanned in memory; nothing is written into the fixture. Exit codes: 0 when every mention passes and there are no unexpected occurrences; 1 otherwise; 2 when the key or the campaign cannot be read.

## Running the suite

`runners/run-suite.mjs` runs every case under `cases/` through its runner, one child process per (case, run), at most `--parallel` at a time (default 8). The child uses the runner's default model (`sonnet`) unless `--model` is given. Each child appends its own record to `results/`. Before the jobs, the suite runs the core purity check (see below) and prints its summary line; the check is one extra row, `core-purity`, and is not counted in the TOTAL line. The suite prints a table of `p/n` per case, a TOTAL line and the reasons of the failed jobs, and exits 0 only when every job and the purity check pass.

```sh
node testbench/runners/run-suite.mjs --no-purity                     # quick: one run per case, audit, world and convert skipped
node testbench/runners/run-suite.mjs --runs 3 --with-audit --no-purity  # release measurement
node testbench/runners/run-suite.mjs --only entry/ --no-purity       # a subset
node testbench/runners/run-suite.mjs --with-world --only world/ --no-purity  # the world cases (only when the world path changed)
node testbench/runners/run-suite.mjs --with-world --only convert/ --no-purity # the convert case (long and costly)
node testbench/runners/run-suite.mjs --with-atlas --only atlas/ --no-purity  # the atlas cases (paid; only when the atlas path changed)
```

The import, plot and system kinds run by default, like entry. `--only world/` without `--with-world` runs nothing for the world cases and says so on stderr. The same holds for `--only convert/` without `--with-world`, and for `--only atlas/` without `--with-atlas`.

## Metrics, regression gate and core purity

```sh
node testbench/runners/metrics-report.mjs [--case <substring>] [--json]
node testbench/runners/regression-gate.mjs [--tolerance 0.34]
node testbench/runners/check-core-purity.mjs
```

- `metrics-report.mjs` prints one row per case, per model and instruction hash: pass rate, stability, failing checks, time and call overruns, median minutes and cost.
- `regression-gate.mjs` compares the latest record set of each case and model with the previous one. A drop of more than one run in three (`--tolerance 0.34`) blocks a release (author decision, 2026-11-21). It exits 1 when blocked.
- `check-core-purity.mjs` checks that the core of the framework (`yllir/scripts`, `yllir/skills`, `yllir/agents`, `yllir/templates`) names no game system and no fixture world. The terms are in `runners/core-purity.yaml`; justified exceptions are in its `allow` list. The suite runs it first unless `--no-purity` is given.

## Unit tests

```sh
cd testbench && find runners -name '*.test.mjs' | xargs node --test
```

A bare directory fails on Node 24, so the files are listed with `find`.

These cover the grading helpers, the limits, the suite, the update runner's grading, the world grading (on temporary copies of the fixtures, with synthetic documents written in place of the agent), the judge's reply parser and prompt, and the delegation rewrite (on temporary copies of the plugin). They run offline.
